# Передача команде hype: события, ачивки и лидерборды

Реализованы Core Below, Capsule Rift, VP Truck Survivors, Build Ways Duel Club и
локальная «По ту сторону экрана». Luchador Runner исключён по просьбе Андрея.

Отдельные таблицы id, условий, уровней, скрытости и правил рейтинга:

- [Core Below](../fruit-fuse-online/HYPE_INTEGRATION.md)
- [Capsule Rift](https://github.com/korandrey1337-hub/rift/blob/main/capsule-rift/HYPE_INTEGRATION.md)
- [Truck](https://github.com/korandrey1337-hub/truck/blob/main/wb_truck_survivor/HYPE_INTEGRATION.md)
- [Build Ways](https://github.com/korandrey1337-hub/roulette/blob/main/roulette-club/HYPE_INTEGRATION.md)
- [По ту сторону экрана](https://github.com/korandrey1337-hub/screenstory/blob/main/screen-story-refactor/HYPE_INTEGRATION.md)

Иконки не требуются: используются стандартные значки хаба.
Сама игра не создаёт профильный раздел, недельные рейтинги или ачивки в каталоге.
Команде хаба нужно зарегистрировать эти таблицы и настроить рейтинги на своей стороне.

| Игра | Метрика | Агрегация | Ограничение |
|---|---|---|---|
| Core Below | depth, устранённые аварии | лучший | точный максимум 4 |
| Capsule Rift | depth, достигнутый этап | лучший | бесконечная; предложенный порог 10000 требует согласования |
| Truck | score | лучший | бесконечная; предложенный порог 1000000000 требует согласования |
| Build Ways | won | сумма | максимум одна победа на игрока за партию; solo/online указаны в mode |
| По ту сторону экрана | нет | нет | история, рейтинг не нужен |

## Что проверить в настоящем хабе

1. Зарегистрировать перечисленные id ачивок и уровни; проверить цветную/серую выдачу.
2. Завершить победу и поражение, убедиться в одном run_end на игрока за партию.
3. Проверить строку забегов/побед/глубины в кампании админки @playhype_bot.
4. Проверить закрытие голосового канала только после конца всей сетевой партии.
5. Проверить mode=solo/online в статистике Build Ways; серия ачивки считает только online.
6. Открыть другую игру и убедиться, что её ачивки, серия и облачные ключи отдельные.

Все новые события идут через клиентский Hub.event. Подписанный серверный POST
не выдуман по неполному примеру: для него нужен docs/HUB_EVENTS.md, раздел 8.
Серверный секрет не добавлялся в браузер или репозиторий.
Без серверного контракта не гарантируется событие после принудительного закрытия
приложения, доставка при потере сети или защита результатов от подделки в консоли.
Выход одного игрока из активного сетевого матча не отправляет ранний run_end,
чтобы не закрыть общий голос. Если игрок не вернулся и не получил финал, его отказ
нужно будет дослать с сервера после реализации точного контракта API.
SDK не подтверждает получение событий: локальная защита от дублей не является
гарантией exactly-once на сервере хаба.

## Проверки

Это межрепозиторный набор тестов, а не тест только Core Below.
Из корня `game` выполните `node --test tools/hub-events/gameplay.test.mjs`.
Для него нужны остальные репозитории в следующих вложенных папках:

```sh
git clone https://github.com/korandrey1337-hub/rift.git rift-publish
git clone https://github.com/korandrey1337-hub/truck.git truck-publish
git clone https://github.com/korandrey1337-hub/roulette.git roulette-repo
git clone https://github.com/korandrey1337-hub/screenstory.git screenstory-publish
```

Существующие рабочие папки повторно клонировать не нужно. Регрессионные тесты
Core Below и Build Ways запускаются отдельно из соответствующих папок игр.
Тесты событий изолированы от боевого хаба: реальные XP/победы не накручиваются.
